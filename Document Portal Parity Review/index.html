01

Verdict

The portal's code is ready for production. Its hosting is not.

It matches the baseline

34 of the 44 portal files on the baseline branch are byte-identical on the host. The other 10 are a build stamp, five re-encoded logos and four files the packager leaves out, two of which belong on the host (P11). The deployed config wires all seven endpoints and matches the delivered-build ledger key for key.

It leads the Agency estate

It ties DL4ALL for the best home-page accessibility and SEO scores, scores 100 for accessibility on Track and Support, and has the smallest pages (272 KB against 0.6 to 5 MB). It makes no third-party requests. It is the only Agency channel where a member of the public can submit a document and track it without an account.

It trails on hosting and trust

It is the only one of the five not on a nitda.gov.ng address. It serves itself over plain HTTP, tells browsers to cache pages and its endpoint config for 30 days, and sends unknown URLs to the host's error site. Its phone number and hours differ from those the Agency publishes.

6 before launch 5 next release 3 improve Four of the six launch items (P1–P4) are properties of the host, not the code. Moving to an Agency-controlled host settles them together.

05

Portal findings

Fourteen findings, in the order to act on them. Each names who can act: the host (server or hosting choice), the portal code (a change and redeploy), the content owner, or an owner decision.

P1

The portal is not on an Agency address, and its host checks every visitor for bots

Before launchOwner decision · Host
Evidence
The portal runs on folio-portal.page.gd under a certificate issued to page.gd, which is shared by every site on that free domain. All four Agency sites sit on nitda.gov.ng addresses. The portal's own header says "An official portal of the Federal Republic of Nigeria". NITDA's 2026 Service Charter (§5.1) presents .gov.ng names as what gives government websites their credibility. The free host also answers any visitor without its test cookie with a JavaScript challenge (aes.js). In our tests WhatsApp, X, LinkedIn, Telegram and Slack link previews received the challenge instead of the page, UptimeRobot received 403, and the browser's manifest request received HTML (P10). The repository already records that this host breaks service-worker registration (scripts/config-build.mjs, 17 Oct 2026).
Fix
Publish the same package at an Agency-controlled address, such as a nitda.gov.ng subdomain, on a static host with no challenge. The config file deploys unchanged because the flow addresses do not move. The move needs a Flow Configuration ALLOWED_ORIGIN row for the new origin, robots.txt and sitemap.xml regenerated, and one flow-package release: 21 package files load the email logos from folio-portal.page.gd/email-assets/. A host that lets you set redirects, headers and an error page also settles P2, P3, P4, P10 and P12.
P2

HTTPS is not enforced

Before launchHost
Evidence
http://folio-portal.page.gd/ serves the whole portal with no redirect and no HSTS header. Over HTTP the page is not a secure context, which has three effects. The scripts and config.local.js, with all seven signed flow URLs, travel unencrypted and can be altered in transit. crypto.subtle is unavailable, so the wizard declares every attachment with an empty SHA-256 (js/submit.js:355); the upload flow package records the declared value and has no step that recomputes it. The clipboard API is off. Flow calls from an HTTP page would also carry an http:// origin, which the allow-list would need to name. We did not test that, because no flow was called.
Fix
Redirect every HTTP request to HTTPS with a 301 at the host, then add Strict-Transport-Security.
P3

Pages, scripts and the endpoint config are cached for 30 days

Before launchHost
Evidence
Every HTML page, js/*.js, sw.js and config.local.js is served with Cache-Control: max-age=2592000, public. A returning visitor's browser reuses its copy for up to 30 days without asking the server. After a config rebuild that changes a signed URL (npm run config:rebuild), those visitors keep calling the old address until their copy expires. After a code release, they keep the old code. The package README asks for no-cache on sw.js (deployment checklist, step 3).
Fix
Serve *.html, js/, config.local.js, sw.js and manifest.webmanifest with Cache-Control: no-cache so browsers revalidate against the ETag. Keep long caching for fonts and images.
P4

Unknown addresses leave the portal

Before launchHost
Evidence
Any unknown path answers 302 to errors.infinityfree.net/errors/404/, the host's own generic error page on another domain. The portal's own 404.html never appears. That page tells someone who followed a link in an official notification to write to portal@nitda.gov.ng. nitda.gov.ng and the LMS both return their own 404 page.
Fix
Point the host's 404 handler at /404.html (ErrorDocument 404 /404.html on Apache-style hosts).
Draft host rules for P2 to P4 and P12 (untested on this host)

Apache-style .htaccess for the site root. InfinityFree sits behind a proxy, so test on a spare path first: a redirect rule that cannot see the original scheme will loop.

RewriteEngine On
RewriteCond %{HTTPS} !=on
RewriteCond %{HTTP:X-Forwarded-Proto} !=https
RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]

ErrorDocument 404 /404.html

<IfModule mod_headers.c>
  <FilesMatch "\.(html|js|webmanifest)$">
    Header set Cache-Control "no-cache"
  </FilesMatch>
  <FilesMatch "\.(woff2|png|svg)$">
    Header set Cache-Control "public, max-age=2592000"
  </FilesMatch>
  Header always set Strict-Transport-Security "max-age=31536000"
  Header always set X-Content-Type-Options "nosniff"
  Header always set X-Frame-Options "DENY"
  Header always set Referrer-Policy "strict-origin-when-cross-origin"
</IfModule>
P5

Contact details contradict the Agency's

Before launchContent owner
Evidence
The portal's telephone, +234 700 000 6483, appears nowhere else in the estate, and the repository records no source for it. nitda.gov.ng, the LMS and the 2026 Service Charter all give +234 816 840 1851. The hours disagree three ways: the portal says 08:00 to 17:00, nitda.gov.ng says 08:30 to 16:30, and the Charter says 9am to 4pm. See the contact comparison.
Fix
Confirm the registry line and hours with the registry and the SERVICOM unit. Then update PF.ORG and PF.CHANNELS in js/data.js, the helpdesk row in js/support.js, and the footer of each HTML page, where the number and hours are written out.
P6

There is no privacy notice

Before launchContent owner · DPO
Evidence
The portal collects name, official email, telephone, organisation, state and documents. The consent checkbox cites the Nigeria Data Protection Act and the support page names dpo@nitda.gov.ng. No page or link says what the data is used for, how long it is kept, who it is shared with, or what rights the person has. nitda.gov.ng links a privacy policy and a cookies policy from every footer, though its policy is made under the NDPR 2019, not the NDPA 2023.
Fix
Publish a portal privacy notice under the NDPA 2023. Link it from the footer, the consent checkbox and the review step of the wizard.
P7

A "JavaScript is required" warning flashes on every page

Next releasePortal code
Evidence
Each page renders the .pf-nojs warning box, and core.js removes it only once it runs (js/core.js:936). Visitors who have JavaScript see a false warning for about a second, then the page jumps up by 123 px. Measured layout shift on a phone: Submit 0.887 (Google's "poor" band starts at 0.25), Home 0.168, Track and Support 0.132.
Fix
The inline script in each page's head already runs before first paint to set the theme. Have it also add a class to <html>, and hide .pf-nojs under that class. Wrapping the box in <noscript> also works.
P8

This browser's own numbers are presented as the registry's

Next releasePortal code
Evidence
"Registry activity", "Requests in the registry", "Received in the last 7 days" and the "requests in progress" ribbon on every page count only the records stored in the visitor's own browser (PF.metrics, js/core.js:615). A first-time visitor is told "No submissions in the register yet". On the Support page, "Accepting documents", "Helpdesk: Open" and the footer's "All portal services operational" are fixed text. We saw "Open" at 03:11 WAT. The live clock shows the device's local time labelled WAT. The package README itself names presenting device data as the registry's answer as the failure the portal was rebuilt to avoid.
Fix
Relabel the counts "Your requests on this device", or remove them until the registry offers a public count. Drive the status rows from real checks or remove them. Compute the clock in the Africa/Lagos time zone.
P9

Colour contrast fails in the light and dark themes

Next releasePortal code (design tokens)
Evidence
axe-core, WCAG 2.1 AA, run in each theme.
  • Light: 11 px muted grey #807D7E on white reaches 4.07:1 against the 4.5:1 required. 11 elements on Home and 9 on Submit, including the step counter and type tags.
  • Dark: the brand green #05583B is used as text on #0B1410 at 2.19:1. This affects the current navigation item, hero emphasis, secondary buttons, FAQ questions and reset buttons: 21 elements on Home, 14 on Submit, 4 on Support and 2 on Track.
  • High contrast: no failures on any page.
Fix
Darken the subtle-text token in the light theme. In the dark theme, map text and outline greens to a light step such as green-300 (#6FAE8E).
P10

"Install as app" and offline mode do not work on this host

Next releasePortal code · Host
Evidence
Browsers fetch manifest.webmanifest without cookies, so the host answers with its challenge page. Chrome logs "Manifest: Line 1, column 1, Syntax error". The deployed config sets serviceWorker: false, so the offline shell is off. The README's "Built in" list still promises an installable app with an offline shell.
Fix
On this host, adding crossorigin="use-credentials" to the manifest link should let the cookie through (untested). P1 removes the cause. Until then, take the claim out of the README.
P11

No robots.txt or sitemap at the live root

Next releasePortal build
Evidence
The packager drops both files from the portal zip (scripts/config-build.mjs:40, PORTAL_NOT_AT_SUBPATH) because they only make sense at a host root. The root-hosted zip inherits that, so /robots.txt answers 302 to the host's error page. The repository copies name activityweb.page.gd, which scripts/platforms.config.mjs:85 records as serving an older portal. ITEM-42 was closed against that older origin and the portal moved on 19 Oct 2026, so this is a new observation. It is not evidence against that closure.
Fix
Regenerate both with node scripts/portal-seo.mjs --origin <production origin> and include them in the root zip.
P12

No security headers, and HTTP/1.1 only

ImproveHost
Evidence
The portal sends none of HSTS, Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy or Permissions-Policy, so any site can frame the submission page. nitda.gov.ng sends frame protection and the Compliance Portal sends X-Frame-Options. No site in the estate sends HSTS. nitda.gov.ng and the LMS serve HTTP/2 (the LMS also HTTP/3); the portal's 30 small requests per page would benefit.
Fix
Set the headers at the host. The portal loads no third-party script, so a strict CSP is achievable. It needs a hash for the inline theme script and connect-src for the Power Platform host.
P13

Shared links show no preview

ImprovePortal code
Evidence
No page carries Open Graph, Twitter card or canonical tags, and most preview bots receive the host challenge anyway (P1). The LMS publishes Open Graph, a Twitter card and JSON-LD.
Fix
Add og:title, og:description, og:image (the lockup), og:url and a canonical link to each page.
P14

Some Service Charter commitments are not reflected yet

ImproveContent owner · Portal code
Evidence
The Charter has officers administer, and customers complete, a customer feedback form (§8.1 v, §8.2 iv), and the SERVICOM unit reports a satisfaction index. The portal collects no feedback after a decision or a closed case. §10 promises the Charter in Hausa, Igbo and Yoruba; the portal is English only, as are the four other sites. nitda.gov.ng links reportgov.ng for service complaints; the portal does not mention SERVICOM or the grievance route. See the Charter comparison.
Fix
Add a one-question satisfaction prompt to the decision timeline and to closed helpdesk cases. Link the Charter and the grievance route from the Support page.

What we saw on the other Agency sites

These are outside the portal's scope. They are listed for the teams that run each site, because two of them are more serious than anything found on the portal.

Compliance Portal

clearance.nitda.gov.ng
  • The sign-in page works over plain HTTP. http:// redirects to http://…/system/login, whose form posts the password to an http:// address.
  • "Forgot password" returns HTTP 500 (Server Error), so users cannot recover their accounts.
  • Headers show nginx 1.14.0. The connection negotiates TLS 1.2, and the footer reads © 2018.
  • The sign-in page weighs 1.7 MB; Lighthouse mobile performance is 56.

NITDA website

nitda.gov.ng
  • Headers announce PHP 7.4.33, which has received no security fixes since November 2022, and Plesk.
  • The 5 MB home page takes 21 s to show its main content on a simulated phone, and shifts by 0.84 while it loads.
  • The home page has 12 empty h1 headings, 20 unnamed links, no skip link and no main landmark.
  • The footer "Contact Us" link is malformed and returns 403. The privacy policy cites the NDPR 2019.

LMS Portal

lms.nitda.gov.ng
  • The viewport disables pinch zoom (user-scalable=0, maximum-scale=1.0), a WCAG 1.4.4 failure on every page.
  • The server takes 3.4 to 5.4 s to respond from the test location.
  • The Courses page has 202 contrast failures.
  • Every guest gets a 30-day "user online" cookie, with no notice.

DL4ALL Dashboard

dashboard.digitalliteracy.nitda.gov.ng
  • Unknown addresses, robots.txt and sitemap.xml all redirect to the home page.
  • Headers announce Next.js. Mobile layout shift is 0.33.
  • Done well: its session cookies use the __Host- and __Secure- prefixes and are HttpOnly and Secure. It also publishes API documentation.

Across all five sites: none sends HSTS, none publishes a security.txt, and none offers a language other than English.

Method and limits

How it was measured

When

Chromium via Playwright 1.56.1, desktop 1366×800 and phone 390×844

Also checked
TLS certificates, HTTP-to-HTTPS redirects, robots.txt, sitemaps, security.txt, link-preview and monitoring user agents, email-client image fetches, the 2026 Service Charter PDF

What it did not do, and what that limits

  • No sign-ins and no form submissions on any site. Every request to a Power Automate host was blocked by the test browser; none was attempted, so no tenant record was created.
  • The portal's config.local.js was read in memory. Only host names, workflow ids and SHA-256 digests were kept.
  • The repository was only read. Nothing was committed, pushed or changed on the baseline branch.
  • The tests ran from a cloud network outside Nigeria, through a proxy. Response times compare sites with each other; they are not what users in Nigeria see.
  • Hosts outside the network allow-list (X, YouTube, reCAPTCHA, the DL4ALL data API) were blocked. That lowers measured page weight and adds console errors on nitda.gov.ng, the Compliance Portal and DL4ALL.
  • The HTTP-to-HTTPS redirect on nitda.gov.ng could not be tested. Signed-in areas of the sibling sites were not assessed.
  • The email logos were checked separately: Gmail, Outlook and Yahoo image proxies receive the real PNGs, because the host challenges only HTML pages.
